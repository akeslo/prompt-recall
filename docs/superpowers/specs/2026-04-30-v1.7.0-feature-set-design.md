# v1.7.0 Feature Set Design

**Date:** 2026-04-30  
**Scope:** Five user-feedback features: image-from-URL, theme color, font size, scheduled auto-backup, sort direction toggle.

---

## 1. Image URL for Before/After

### Problem
Before/After media slots only accept file upload and drag-drop. Users want to paste an image URL directly.

### Design
Each media slot in the Add/Edit modal gets a **"From URL"** button below the slot area. Clicking it reveals an inline `<input type="url">` + "Load" button. On confirm:

1. Popup sends `{ action: 'fetchImageUrl', url }` to background via `chrome.runtime.sendMessage`.
2. Background service worker fetches the URL using `fetch()` (no CORS restriction in SW), converts response to blob, then to base64 data URL via `FileReader`, and sends it back in the response callback.
3. Popup receives the data URL, runs it through the existing `compressImage()` pipeline (480px max, JPEG 0.78), stores in `mediaEditorState[slot]`, and calls `applyMediaSlotImage()`.

**Error handling:** Non-image content type, fetch failure, or timeout (10s) shows inline error text inside the slot ("Could not load image from URL"). No global notification — keeps error scoped to the slot.

**Manifest change:** No new permissions needed — service worker can fetch arbitrary URLs by default in MV3.

## 2. Theme Color

### Problem
Accent color (`--accent: #34d4a8`) is hardcoded. Users want to personalize it.

### Design
Settings modal gets a new **"Theme"** section above "Samples":

- 6 preset color swatches: Teal `#34d4a8` (default), Blue `#5b9cf6`, Purple `#a78bfa`, Orange `#f59e0b`, Pink `#f472b6`, Red `#f87171`
- A `+` swatch (dashed border) that opens the native `<input type="color">` picker for any hex value
- Active swatch shows a checkmark ring overlay

**Storage:** `chrome.storage.local` key `accentColor` (hex string, e.g. `"#5b9cf6"`).

**Application:**
```js
function applyAccentColor(hex) {
  const r = document.documentElement;
  r.style.setProperty('--accent', hex);
  r.style.setProperty('--accent-bg', hex + '1a');   // ~10% opacity
  r.style.setProperty('--accent-bdr', hex + '40');  // ~25% opacity
  r.style.setProperty('--success-color', hex);
}
```
Called on popup load (after storage read) and on swatch click. No page flash — applied before first render in `init()`.

**Reset:** Clicking the active teal swatch again resets to default and removes the `accentColor` key.

## 3. Font Size

### Problem
Font size is fixed at 13px. Users want larger text for readability.

### Design
Settings modal gets a **"Font Size"** row in a new "Appearance" section (shares section with Theme):

- Three toggle buttons: `S` (12px) / `M` (13px, default) / `L` (15px)
- Active button is highlighted

**Storage:** `chrome.storage.local` key `fontSize` (`"s"` | `"m"` | `"l"`).

**Application:** CSS class on `<body>`: `font-size-s`, `font-size-m`, `font-size-l`. CSS targets:
```css
body.font-size-s { --fs-base: 12px; }
body.font-size-m { --fs-base: 13px; }  /* default */
body.font-size-l { --fs-base: 15px; }

.prompt-content,
.prompt-title,
.meta-text,
.tag { font-size: var(--fs-base); }
```
Applied on popup load before render. Default M = current behavior, no visual regression.

## 4. Scheduled Auto-Backup

### Problem
Users want automatic periodic backups to their local Downloads folder without manual export.

### Design

**Manifest additions:**
```json
"permissions": ["storage", "contextMenus", "clipboardWrite", "alarms", "downloads"]
```

**Settings section: "Auto-Backup"**
- Toggle: enabled/disabled
- Interval select: 30 min / 1 hr / 6 hr / 24 hr (default 6 hr)
- Last backup timestamp shown as hint text: "Last backup: 2h ago" or "Never"

**Storage keys (`chrome.storage.local`):**
- `autoBackupEnabled`: boolean
- `autoBackupInterval`: number (minutes: 30, 60, 360, 1440)
- `autoBackupLastTs`: timestamp (ms)

**Alarm flow:**
1. User enables toggle → popup calls `chrome.alarms.create('autoBackup', { periodInMinutes })`.
2. User disables toggle → popup calls `chrome.alarms.clear('autoBackup')`.
3. User changes interval → clear + recreate alarm.
4. Service worker `chrome.alarms.onAlarm` listener checks `alarm.name === 'autoBackup'`, reads `autoBackupEnabled` (guard against stale alarms), fetches all prompts from `chrome.storage`, serializes to JSON blob as a data URL (`data:application/json;base64,...`), calls `chrome.downloads.create({ url, filename: 'prompt-recall-backup-<ISO-date>.json', saveAs: false })`.
5. On success, sets `autoBackupLastTs`.

**Restart resilience:** Service worker `chrome.runtime.onStartup` and `chrome.runtime.onInstalled` listeners re-register the alarm if `autoBackupEnabled` is true (Chrome clears alarms on SW restart).

**Interval change:** Popup saves new interval to storage, clears old alarm, creates new one.

## 5. Sort Direction Toggle

### Problem
Only one direction available per sort mode. Users want A→Z and Z→A, Most Recent and Oldest.

### Design
A small `↑` / `↓` icon button placed immediately right of the sort `<select>` in the controls bar. 

- `↓` = descending (default, current behavior)
- `↑` = ascending (reversed)

**Storage:** `chrome.storage.local` key `sortDirection` (`"asc"` | `"desc"`), default `"desc"`.

**Sort logic in `applyFiltersAndSort()`:**
```js
const dir = state.sortDirection === 'asc' ? -1 : 1;
// In each comparator, multiply final result by `dir`
// Pinned-first logic still applies when dir === -1 (pins stay on top regardless)
```

**Disabled state:** Button is disabled and faded when sort mode is `"favorites"` (direction meaningless for a filter-only mode).

**Persistence:** Loaded from storage in `init()` alongside `viewMode` and `sortSelect` value.

## Constraints & Non-Goals

- Auto-backup uses `saveAs: false` — file goes straight to Downloads, no dialog per backup.
- Image URL fetch limited to 10s timeout; max compressed size same as file upload (480px, JPEG 0.78).
- No sync to cloud, no arbitrary file path write (Chrome API limitation).
- No dark/light mode toggle (out of scope).
